# Provenance and Broadcaster

The independent Source service defaults to `https://provenance.invisipay.fi`. Configure trusted chain/protocol scope, generation, provider, Ed25519 signing keys and manifest locally; responses cannot establish trust. Scope contains chain and protocol only. Source circuits have 11 public inputs and capacities 10, 20, 40, 80, 120, 160 and 190. Root certificate payloads contain exactly 269 bytes and signatures contain 64 raw Ed25519 bytes.

The checked-in Source manifest SHA-256 is `6107789c5c0d24c4130bff05da6d389336feb5ccb247c4030eae5198ab05d762`. Run `python3 scripts/sync-provenance.py ../invisi-protocol` to authenticate and copy local public circuit artifacts and VKs. Main payment circuits and Source assets remain separate. All witnesses and proving stay local.

`PreparedProvenance::from_local_configuration` installs the pinned Source client, offline prover, authenticated manifest and replay budgets. Attach this capability through `Invisi::with_provenance` or a restored prepared transaction's `reattach_provenance`. The SDK authenticates certificates and chain anchors, replays public leaves locally and selects a supported Source capacity without disclosing private openings or querying individual Note commitments.

Normal direct payment preparation, authorization and proving do not require Source or Broadcaster. For a final proved private Note payment, call `prove_provenance(chain)` to obtain a complete `ProvenanceProof` public packet. It contains `format`, exact final `data`, public deployment/token `context`, `mainCircuitCapacity`, complete native `publicInputs`, `operationDigest` and Source `sidecars`. It contains no Note plaintext, private witness or local proving capability. Explicit proving can run before payment or after confirmation; it encodes the retained final call without requiring the original inputs to remain unspent or the payment deadline to remain fresh. Source certificates still require trusted signatures and canonical primary anchors.

Serialize the returned packet independently. `sdk::validate_provenance_proof(&packet, &trust)` re-decodes canonical private transact calldata, reconstructs its complete native statement, checks the operation digest and ordered nullifiers, and authenticates the Source bundle and certificates. `sdk::submit_provenance_proof(&client, &packet)` performs the same checks and sends `provenance_submitSourceProof {data, proofSidecars}`. This public packet resubmission needs no wallet, private prepared snapshot, prover, transaction hash or caller-assigned ID. Source automatically matches the transaction on chain before or after admission. Primary payment settlement and off-chain recognition remain separate outcomes.

For relayed payment, `with_broadcaster` rebuilds the unsigned business plan until `broadcaster_estimateQuote` fees converge, then obtains a separate signed `broadcaster_getQuote`. Consent and main proving follow the final quote. Quotes advertise `provenanceRequired`; their Source intent hash is `keccak256(abi.encode("InvisiBroadcasterProvenanceIntentV1", originalRequestHash))`. Only the ready transaction's submission builds required Source evidence. Quote requests do not include proof sidecars. Shield and Credit lifecycle calls do not require private Note membership proofs.

The Broadcaster assigns opaque submission IDs. A local retry key is never sent as a service submission ID. Session journals retain the exact public request before sending and persist the returned server ID separately. A lost initial response retries the exact retained request; an acknowledged request first queries the server ID. A lookup outage does not trigger another send. Server status never finalizes wallet state without primary-chain reconciliation.

`examples/07-broadcaster` contains prepare/broadcast, final-payment public packet proving/submission, and independent public packet recovery/submission examples. All examples require `--execute` before opening configuration or contacting services. Flat Source environment settings contain public trust pins; proving additionally uses local executable paths. The application protects private prepared snapshots and supplies ordinary wallet signing and delivery decryption implementations. Example 02 accepts a private application-managed prepared snapshot (the example loader reads JSON; the App must decrypt its protected storage before passing it) to prove, prints the public packet and submits the packet. Example 03 reads only that public packet and the public pins from flat environment settings; it opens no payment state or local prover assets.

Explicit `ProvenanceRecovery` supports encrypted CAS persistence, bounded public proof jobs and tracking polling. It never resends a main payment. Source RPC helpers reject private-material field names, reserved internal idempotency prefixes, mismatched trust identities, stale generations and inconsistent proof statements.
